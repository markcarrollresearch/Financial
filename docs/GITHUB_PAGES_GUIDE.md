# Open Financial Lab as a website

You do not need to download the ZIP, install anything, or type commands. The website files are already prepared in your GitHub repository.

## One-time setup

1. Sign in to GitHub as **markcarrollresearch**.
2. Open [your Financial repository's Pages settings](https://github.com/markcarrollresearch/Financial/settings/pages).
3. Find **Build and deployment**. For **Source**, choose **Deploy from a branch**.
4. Under **Branch**, choose these two options:

   | Dropdown    | Choose                     |
   | ----------- | -------------------------- |
   | Branch name | **financial-lab-delivery** |
   | Folder      | **/docs**                  |

5. Click **Save**.
6. Wait several minutes and refresh the settings page. When GitHub shows **Your site is live**, click **Visit site**.

The address should be **https://markcarrollresearch.github.io/Financial/** once GitHub finishes publishing. That is the app's web address, not the GitHub code/download page.

## Each time you use it

Open the website address in Edge or Chrome. Bookmark it. Use the same address on your Samsung tablet and turn the tablet sideways. No application installation or terminal is needed. This hosted version needs an internet connection.

The site is public. Visitors do not need your GitHub password or a ChatGPT account. It uses synthetic financial transactions, with the independent-interview disclosure visible in the app.

## A simple first check

On **Executive overview**, select **All divisions**. The exact YTD budget should read **$9,615,367.31**. Use the left menu to explore Revenue assurance, Accounts receivable and Decision Lab. Tap an exception or invoice for its details.

## If something looks different

- If the settings page is missing or asks you to sign in, check that you are using the GitHub account that owns this repository.
- If you cannot see **financial-lab-delivery**, refresh the settings page and open the branch dropdown again.
- If the folder is **/(root)**, change it to **/docs** before saving.
- If you see a **404** page immediately after saving, give GitHub several minutes to finish, then refresh.
- If the site still fails, return to this chat with the message shown on the screen. No passwords or tokens are needed in chat.

Publication is not confirmed just because the files have been uploaded. After saving, the actual public address must be checked. The cloud session could upload the files through Git, but its GitHub administration API request was blocked, so enabling Pages is the one account setting left for you.
